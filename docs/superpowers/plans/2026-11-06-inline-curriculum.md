# Inline curriculum editor

Approved follow-up: edit directly on the CV layout; remove the separate input-form and preview interface. Remove introductory marketing text, footer, sidebar note and persistent success banners. Use DM Sans in app, editable CV and PDF. Keep locale labels 🇬🇧 EN / 🇮🇹 IT with adequate padding; keep browser-only named/date history, all unsaved guards and local CMS import without browser login.

Implementation:
1. Extend the shared CV renderer with opt-in editable markup (default PDF remains free of editing controls). Text fields contenteditable plaintext-only; individual bullets editable, Enter adds a bullet; contextual date/link dialogs and entry/section controls. Empty printable fields show editor-only placeholders so they remain reachable. No model/history schema changes.
2. Replace form/preview UI with one A4 canvas and compact section controls. Sidebar on wide screens; compact section selector on narrow screens. Fit/zoom controls support small viewports. Changes update the model immediately without re-rendering the active field. Guard loads/unloads as before and disable canvas editing during imports.
3. Bundle DM Sans locally with license. Serve local font in app/canvas and embed the exact font bytes in exported PDFs for reliable offline printing. Font loading must complete before PDF output.
4. Test editable-to-model mapping including bullets/multiline/paste, contextual dates/links, add/remove/reorder/hide, saved history compatibility, unsaved guards, loading locks, responsive layouts and PDF parity. Visually inspect screenshots/PDF and verify embedded font. Keep changes local in commits and update PR draft.

Interfaces: renderCV(source, locale=source.locale, options={editable:false,fontURL:'/fonts/dm-sans.woff2'}) returns complete trusted HTML. Editor fields have data-field canonical document paths and optional data-line for multiline bullets. Context buttons carry data-details='dates|link', data-path and optional data-link='linkedin|github'. Entry controls carry data-action, data-key and data-index. Shared plain document/History key remain unchanged.

Final implementation decisions: the editable paper is a same-page ShadowRoot, which scopes the CV stylesheet without an embedded browser document. Handlers bind once on that stable root; text updates synchronously, and bullet splits/merges update the list in place. Fit/zoom applies to the paper while normal page scrolling remains available. The renderer remains the single source for paper markup and printable content. The app uses the bundled variable WOFF2; PDF output uses bundled static 400/500/600/700 TTF faces (options.fontFaces), embedded as data URIs, to retain reliable text extraction. Ligatures are disabled in both views. No history/document schema changes.
